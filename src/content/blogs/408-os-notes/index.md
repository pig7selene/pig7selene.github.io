# 1.计算机系统概述

## 1.1 OS的基本概念

### 1.1.1 OS的概念

计算机系统自下而上可分为硬件，操作系统，应用程序和用户，OS负责管理硬件资源，为应用提供运行环境，充当硬件和用户的桥梁

### 1.1.2 OS的功能和目标

功能：处理机管理（进程管理），存储器管理，设备管理（处理IO请求等）和文件管理，提供借口，通过抽象/虚拟化扩充硬件功能

**接口**

- 联机用户接口（CLI）
- 脱机用户接口（作业控制语言）
- GUI
- 程序接口（本质是系统调用）

目的：提供更便捷服务，提升资源利用率

### 1.1.3 操作系统特征

- 并发：一段时间间隔内发生
- 共享：资源供内存中多个并发的进程同时使用，分为互斥共享（一个时间仅允许一个进程），同时共享（逻辑上的并发访问）
- 虚拟：把一个物理资源变成多个逻辑资源，让各个进程感觉自己独占该资源，有时分复用和空分复用
- 异步：多个进程以各自独立、**不可预知**的速度向前推进

## 1.2 操作系统的发展历程

### 1.2.1 手工操作阶段

无操作系统，用户通过纸带或卡片输入程序，人工控制运行。

缺点：用户独占全机，CPU等待人工操作，**人机速度矛盾**导致资源利用率极低。

### 1.2.2 批处理阶段

**单道批处理系统**

引入脱机I/O技术，利用外围机和磁带完成输入/输出准备，由监督程序控制作业自动、依次运行，出现操作系统的雏形。

- 特点：自动性、顺序性、单道性，内存中仅有一道程序
- 优点：减少人工干预，缓解人机速度矛盾
- 缺点：程序进行I/O时CPU只能等待，资源利用率仍较低

**多道批处理系统**

内存中同时存放多道程序，一道程序等待I/O时，CPU可执行其他程序。

- 特点：多道程序**并发**执行、共享资源；单CPU下宏观上并行、微观上串行
- 优点：CPU与I/O设备可并行工作，资源利用率高、吞吐量大
- 缺点：用户响应时间长，**不提供人机交互能力**

### 1.2.3 分时与实时操作系统

**分时操作系统**

将CPU时间划分为短小的时间片，轮流为多个终端用户服务，使各用户感觉独占计算机。

- 特点：同时性、交互性、独立性、及时性
- 优点：支持人机交互，响应较快
- 局限：不能保证任务在严格时限内完成

**实时操作系统**

及时响应外部事件，并在**规定时间内**完成处理，强调**及时性和可靠性**。

- 硬实时：必须按时完成，如导弹制导
- 软实时：允许偶尔超时，如部分多媒体处理任务

区别：分时侧重用户交互和及时响应，实时侧重满足任务的截止时间。

### 1.2.4 其他操作系统

- 网络OS：管理网络通信，实现计算机之间的资源共享
- 分布式OS：协调多台计算机协作，对用户隐藏资源的物理分布
- 微机OS：面向个人计算机，从单用户单任务发展到支持多任务、图形界面等功能

## 1.3 操作系统运行环境

### 1.3.1 操作系统内核

目的：保护核心模块，提升操作系统运行效率

内核的支撑功能主要包括：

- **时钟管理**：计时、处理时钟中断，为进程调度等提供依据。
- **中断处理**：响应中断和异常，转入相应处理程序。
- **原语操作**：提供不可被中断的基本操作，如进程状态修改，保证关键操作的原子性。

系统资源管理功能：

- **处理机（进程）管理**：管理进程，分配CPU，协调进程运行。
- **存储器管理**：分配、回收和保护内存。
- **设备管理**：分配、回收设备，处理I/O请求。
- **文件管理**：组织、存储、读写和保护文件。

### 1.3.2 处理机的双重工作模式

为防止应用程序破坏系统，处理机区分两种工作模式，由PSW中的状态标志标识。

- **用户态（目态）**：运行应用程序，只能执行非特权指令，访问资源受限。
- **内核态（管态、核心态）**：运行操作系统内核，可执行全部指令，访问受保护的系统资源。

**指令分类**

- 特权指令：仅能在内核态执行，如关中断、设置定时器、执行设备I/O。
- 非特权指令：两种状态下均可执行，如普通算术运算、数据传送。

**状态切换**

- 用户态 → 内核态：发生中断或异常（包括系统调用引起的陷入），由硬件切换。
- 内核态 → 用户态：内核执行返回指令，恢复用户程序运行。

陷入指令不是特权指令，用户程序可通过它请求内核服务；用户态执行特权指令会引发异常。

### 1.3.3 中断和异常的概念

中断和异常使CPU暂停当前程序，转去执行内核中的相应处理程序，是操作系统取得CPU控制权的重要机制。

**分类**

- **中断（外中断）**：分为可屏蔽中断和不可屏蔽中断，来自CPU外部，与当前执行的指令无关，如时钟中断、I/O完成中断。
- **异常（内中断）**：由当前指令执行引起，如非法指令、缺页、执行陷入指令。

**异常的类型**

- 陷入（Trap）：程序主动触发，如通过陷入指令请求系统调用。
- 故障（Fault）：可能被修复，修复后重新执行原指令，如缺页。
- 终止（Abort）：严重且通常无法恢复的错误，需终止程序，如某些硬件故障。

**处理过程**

检测到中断请求信号后 CPU 会打断当前程序，转入中断/异常处理程序，如果可以解决，异常会返回原来的指令执行，中断会返回 i + 1指令执行，不可解决直接终止

 **中断处理与子程序调用的比较**

相同点：都需保存返回地址，转去执行另一段程序，结束后可返回原程序。

| 比较     | 中断处理                   | 子程序调用             |
| -------- | -------------------------- | ---------------------- |
| 触发方式 | 由中断事件触发             | 主动执行调用指令       |
| 发生时机 | 通常不可预知               | 由程序逻辑确定         |
| 入口确定 | 根据中断类型查找           | 由调用指令指定         |
| 保存内容 | 断点、程序状态及必要寄存器 | 返回地址及必要寄存器   |
| 工作模式 | 用户态响应中断时进入内核态 | 普通调用通常不改变模式 |
| 返回方式 | 中断返回指令               | 子程序返回指令         |



### 1.3.4 系统调用

系统调用是操作系统提供给应用程序的程序接口，应用程序通过它请求内核服务，由内核统一管理受保护的资源。

**主要功能**

- 设备管理：申请、释放、读写设备
- 文件管理：创建、删除、读写文件
- 进程控制与通信：创建、撤销进程，传递消息
- 内存管理：分配、回收内存

**执行过程**

传递参数和系统调用号 → 执行陷入指令 → 进入内核态 → 执行相应服务程序 → 恢复现场并返回用户态（正常返回时）。

**与普通函数调用的区别**

- 系统调用：进入内核，由操作系统提供服务，涉及工作模式切换。
- 普通函数调用：通常在原工作模式下执行，不涉及模式切换。
- 库函数可封装系统调用，但**并非所有库函数都需要系统调用**。



## 1.4 操作系统结构

操作系统结构是指各功能模块的组织方式及其相互关系。

**分层法**

将操作系统划分为若干层，每层利用下层服务，并向上层提供服务。

- 优点：层次清晰，便于调试、验证和维护
- 缺点：层次划分困难，逐层调用增加开销

**模块化**

按功能划分模块，通过明确的接口协作，部分模块可按需动态装入或卸载。

- 优点：便于开发、维护和扩展，组合灵活
- 缺点：接口设计复杂，模块间依赖可能影响可靠性

**宏内核（大内核）**

将进程管理、内存管理、文件系统、设备驱动等主要功能放在内核态运行。

- 优点：模块间调用方便，通信开销小，性能较高
- 缺点：结构复杂，维护困难，某个模块出错可能影响整个系统

注意：**模块化与宏内核可以同时采用**，划分模块不代表模块运行在用户态。

**微内核**

内核只保留最基本的功能，如进程间通信、基本内存管理和中断处理，其余服务移到用户态，彼此之间以及和客户进程之间的交互通过微内核提供的消息传递机制

- 优点：模块独立性强，可靠性、可扩展性和可移植性较好
- 缺点：服务间通信及用户态、内核态切换较多，性能开销较大

基本功能

- **低级进程管理**：提供进程调度、切换及进程间通信等基本机制，支持用户态服务之间协作。
- **低级存储器管理**：提供地址映射和内存保护等基本机制，较复杂的内存管理策略交给用户态服务。
- **中断和异常处理**：捕获中断和异常，完成必要处理，并通知相应的用户态服务，如设备驱动程序。

内核保留基本机制，用户态服务负责较复杂的策略和功能，机制和策略分离的设计原则，采用面向对象技术

**外核**

内核主要负责硬件资源的**保护与分配**，由用户态的库操作系统提供具体的资源抽象和管理策略。

- 优点：应用可按需求管理资源，灵活性高，减少不必要的抽象开销
- 缺点：应用开发和资源管理更复杂

## 1.5 操作系统引导

操作系统引导是指计算机启动时，将操作系统内核装入内存并开始运行的过程，也称**启动或自举**

**引导过程（以传统BIOS方式为例）**

1. **CPU激活和BIOS初始化**：CPU从预定地址开始，执行ROM或闪存中的BIOS程序。
2. **硬件自检**：检查内存、处理器等关键硬件，完成必要的初始化。
3. **选择启动设备**：按照设定的启动顺序，寻找可启动的磁盘等设备。
4. **读取主引导记录（MBR）**：将启动磁盘的MBR装入内存，执行其中的引导代码，根据分区表找到活动分区。
5. **定位活动分区并加载分区引导程序(PBR)**：通过活动分区的分区引导记录，进一步加载操作系统引导程序。
6. **加载启动管理器**：PBR里代码负责加载活动分区启动管理器
7. **加载并启动内核**：引导程序将内核装入内存，转交控制权；内核初始化系统资源，启动用户进程及服务，内核接管系统控制权，重建中断处理机制



## 1.6 虚拟机

虚拟机通过虚拟化技术，将一台物理计算机的资源抽象为多台逻辑计算机。每台虚拟机具有独立的运行环境，可安装自己的操作系统。

**第一类（裸机型）**

VMM直接运行在硬件上，无需宿主操作系统。

结构：硬件 → VMM → 客户操作系统 → 应用程序。

特点：资源控制直接，通常性能较高，常用于服务器。

**第二类（寄居型）**

VMM作为应用程序运行在宿主操作系统上，通过宿主操作系统使用硬件资源。

结构：硬件 → 宿主操作系统 → VMM → 客户操作系统 → 应用程序。

特点：安装使用方便，适合个人使用和测试，但依赖宿主操作系统，通常额外开销较大。



# 2.进程与线程

## 2.1 简介

### 2.1.1 进程的概念

**进程**是进程实体的运行过程，是系统进行**资源分配和调度**的独立单位。两大特性：并发性和共享性

进程实体（进程映像）由**程序段、数据段和进程控制块（PCB）**组成：

- 程序段：存放程序指令，描述要完成的功能
- 数据段：存放运行过程中使用和产生的数据
- PCB：记录进程的标识、状态、资源等信息，是进程存在的**唯一标志**

创建进程实质上是建立PCB，撤销进程实质上是撤销PCB。进程实体是静态的，进程是动态的。

**进程与程序的区别**

- 程序是**静态**的指令集合，进程是**动态**的执行过程，有创建、运行和终止的生命周期。
- 程序与进程不一一对应：同一程序多次执行可形成多个进程，一个进程也可先后执行不同程序。

**进程的基本特征**

- **动态性**：随执行而创建、变化、终止，是进程最基本的特征
- **并发性**：多个进程可在同一时间段内交替推进
- **独立性**：能独立获得资源、接受调度
- **异步性**：各进程以独立、不可预知的速度推进
- **结构性**：由程序段、数据段和PCB组成

### 2.1.2 进程的组成

**进程控制块（PCB）**

PCB是操作系统管理进程的数据结构，也是进程存在的**唯一标志**，随进程创建而建立、随进程撤销而撤销。

主要记录：

- **进程标识信息**：进程ID（PID）、用户ID等
- **处理机状态信息**：程序计数器、通用寄存器、程序状态字等，用于保存和恢复CPU现场
- **进程调度信息**：进程状态、优先级、等待事件等
- **资源和内存信息**：程序和数据的地址、已分配资源、进程间通信信息等

操作系统将各进程的PCB以适当方式连接起来，主要有：链接方式和索引方式

**程序段**

程序本身是静态的，可被多个进程共享，存放进程执行的指令，描述进程要完成的功能。同一程序的代码可以被多个进程共享。

**数据段**

每个进程的数据段是私有的，存放程序运行所需的原始数据，以及执行过程中产生的中间结果和最终结果。运行时还需要栈等空间，保存函数参数、局部变量和返回地址等。

### 2.1.4 进程的内存映像

进程的内存映像是进程运行所需的代码、数据及相关状态信息的集合，是一个虚拟地址空间，主要包括：

- **代码段（正文段）**：存放程序指令，通常只读，可被多个进程共享。
- **数据段**：存放全局变量、静态变量等；未初始化或初始化为零的变量通常放在BSS段。
- **堆**：用于运行时动态分配内存，如通过`malloc`申请的空间，通常向高地址增长。
- **栈**：保存函数参数、返回地址、局部变量等，随函数调用自动分配和回收，通常向低地址增长。
- **PCB**：保存进程标识、状态、CPU现场和资源信息，由操作系统管理。不属于进程的虚拟地址空间

### 2.1.4 进程的状态与转换

**进程的五种状态**

- **创建态**：正在建立PCB、分配资源，尚未具备运行条件。
    
- **就绪态**：已具备运行条件，只等待分配CPU。
    
- **运行态**：已获得CPU，正在执行。
    
- **阻塞态（等待态）**：等待某个事件发生，如I/O完成，即使CPU空闲也无法运行。
    
- **终止态**：进程正常结束或异常退出，系统正在回收资源、撤销PCB。
    

**状态转换**

- 创建 → 就绪：创建工作完成，具备运行条件。
    
- **就绪 → 运行**：被调度程序选中，获得CPU。
    
- **运行 → 就绪**：时间片用完，或被更高优先级进程抢占CPU。
    
- **运行 → 阻塞**：需要等待I/O、资源或其他事件。
    
- **阻塞 → 就绪**：等待的事件发生，重新具备运行条件。
    
- 运行 → 终止：执行结束，或因异常而终止。

### 2.1.5 进程控制

进程控制是对进程生命周期的管理，包括创建、终止、阻塞、唤醒和切换，以原语的形式出现

**进程控制原语**

原语是完成特定功能、执行具有**原子性**的基本程序，关键操作不可被中断，避免进程状态、PCB和队列信息不一致。

单CPU系统中，常通过**关中断 → 执行关键操作 → 开中断**保证原子性。

**进程创建**
子进程和父进程是相互独立的实体，拥有各自的PCB和虚拟地址空间

触发：系统初始化、用户启动程序、已有进程请求创建子进程等。

申请PCB → 分配资源 → 初始化PCB → 设置为就绪态，加入就绪队列。

**进程终止**

触发：正常结束、异常退出或被外部请求终止。

检索PCB → 剥夺CPU，触发调度程序 → 释放系统资源 → 若支持级联终止递归终止子孙进程，佛祖额子孙进程继续  →撤销PCB。

**进程阻塞**

进程因等待I/O、资源或其他事件，暂时无法继续执行。是进程的主动行为

保存CPU现场 → PCB状态改为阻塞态 → 加入相应等待队列 → 调度其他进程。

**进程唤醒**

等待的事件发生，由内核或相关进程触发唤醒。

等待队列里找到PCB，从等待队列移出 → 状态改为就绪态 → 加入就绪队列。

注意：**唤醒不等于立即运行**，还需等待CPU调度；阻塞与唤醒通常针对同一等待事件配对使用。

**进程切换**

触发：时间片用完、进程阻塞或终止、更高优先级进程抢占等。

保存原进程现场至PCB → 更新状态及队列 → 选取下一进程 → 恢复其运行环境和CPU现场。

注意：**进程切换涉及不同进程之间的交接；用户态与内核态切换不一定引起进程切换。**

### 2.1.6 进程的通信

进程通信是指进程之间交换信息。各进程的地址空间通常相互独立，因此需要操作系统提供通信机制。分为低级和高级通信

**共享存储**

建立一块可被多个进程访问的共享内存，通过读写该区域交换数据。

- 映射建立后，数据交换无需反复经过内核复制，效率较高
    
- 进程需通过信号量、互斥锁等进行**同步与互斥**，避免数据混乱
    
- 可分为基于数据结构的共享和基于存储区的共享，后者使用更灵活

- 操作系统仅负责分配共享内存区并完成地址映射，不会提供自我保护
    

**消息传递**

进程通过操作系统提供的**发送、接收原语**交换消息，消息通常由消息头和消息体组成。

- 直接通信：明确指定接收或发送消息的进程
    
- 间接通信：通过信箱、消息队列等中间对象收发消息
    

数据传递由操作系统协调，不要求进程共享地址空间。

**管道通信**

管道是内核维护的缓冲区，进程通过读、写操作交换**字节流**数据。

- 普通管道通常是**半双工**的，双向通信需建立两条管道
    
- 读取会取走数据，管道不是可反复读取的普通文件
    
- 阻塞方式下，无数据时读者等待，缓冲区满时写者等待
    
- 匿名管道通常用于有亲缘关系的进程；命名管道可用于无亲缘关系的进程

管道机制需提供的三方面协调能力

- **互斥**：对管道的关键读写操作进行互斥控制，避免并发访问造成数据混乱。
    
- **同步**：管道满时，写进程等待；管道空且仍有写端时，读进程等待。条件满足后唤醒相应进程。
    
- **确定对方是否存在**：判断读端、写端是否仍存在。所有写端关闭且数据读完后，读取返回文件结束；所有读端关闭后，写入会出错。
    

**信号通信**

信号是操作系统向进程发送的**事件通知**，用于告知某种情况发生，使进程作出相应处理，主要用于控制，不适合传递大量数据。在PCB中用一个 $n$ 位向量记录待处理的信号

**信号的产生与传递**

- 内核发送信号
- 进程发送信号（也可以向自己发送）

**信号的处理方式**

- **默认处理**：执行系统规定的动作，如终止、暂停、继续运行或忽略。
    
- **自定义处理**：执行进程事先注册的信号处理函数，正常结束后通常返回原执行位置。

其中，**SIGKILL（强制终止）和SIGSTOP（暂停）不能被捕获、忽略或屏蔽**。

### 2.1.7 线程与多线程模型

**1. 线程的基本概念**

线程是进程中的一个执行流，是**CPU调度的基本单位**；进程是**资源分配的基本单位**。为了进一步降低程序并发执行时的时空开销，增加并发性能

线程的主要属性：
1. 轻量级执行实体：线程ID，程序计数器PC，寄存器集合，栈，每个线程有唯一的标识符和TCB
2. 共享代码段
3. 资源共享
4. 独立调度单位
5. 生命周期
引入线程后，进程成为除CPU以外的系统资源分配单位，线程则成为了CPU调度和执行的基本单位

**2. 线程与进程的比较**

| 比较    | 进程           | 线程                   |
| ----- | ------------ | -------------------- |
| 基本作用  | 资源分配的基本单位    | CPU调度的基本单位           |
| 资源拥有  | 拥有独立的地址空间和资源 | 共享所属进程的资源，保留独立运行现场   |
| 并发性   | 进程之间可并发      | 同一进程的线程之间也可并发        |
| 创建与切换 | 开销较大         | 通常开销较小               |
| 通信    | 通常需借助进程通信机制  | 可直接访问共享数据，但需同步与互斥    |
| 独立性   | 隔离性较强        | 隔离性较弱，一个线程出错可能影响整个进程 |
| 开销    | 开销大          | 只需保存和恢复寄存器状态         |

注意：**同一进程内的线程切换通常无需切换地址空间**；不同进程的线程之间切换仍涉及地址空间切换。

**3. 线程的状态和生命周期**

线程的基本状态包括**就绪、运行、阻塞**。

- 就绪 → 运行：获得CPU。
    
- 运行 → 就绪：时间片用完或被抢占。
    
- 运行 → 阻塞：等待I/O、锁或其他事件。
    
- 阻塞 → 就绪：等待条件满足。
    

生命周期：**创建 → 就绪 → 运行（期间可能就绪或阻塞）→ 终止**。

线程结束后回收自身资源；进程结束时，其内部线程也随之结束。

**4. 线程控制块**

线程控制块（**TCB**）用于记录和管理线程，主要包含：

- 线程标识：线程ID、所属进程等。
	
- 线程当前状态
    
- 调度优先级

- 寄存器集合：程序计数器，状态寄存器，通用寄存器

- 线程局部存储区

- 堆栈指针

线程切换时，保存原线程的现场，恢复下一线程的现场，使其从原位置继续执行。

**5. 线程的实现方式**

**用户级线程（ULT）**

由用户态线程库管理，内核不能直接感知这些线程。

- 优点：管理和切换通常无需进入内核，开销小。可移植性强，调度策略可由应用程序定制
    
- 局限：能否利用多核、阻塞是否影响其他线程，取决于与内核线程的映射方式。
    

**内核级线程（KLT）**

由内核管理和调度，内核可直接感知每个线程。

- 优点：可在多核上并行；一个线程阻塞时，其他线程仍可运行。
    
- 缺点：管理和切换需要内核参与，开销较大。
    

**组合实现与多线程模型**

将用户级线程映射到内核级线程，由线程库和内核共同管理：

- **多对一**：多个用户线程对应一个内核线程。切换开销小，但一个线程执行阻塞式系统调用可能阻塞全部线程，且不能实现多核并行。
    
- **一对一**：每个用户线程对应一个内核线程。支持多核并行，阻塞影响较小，但内核管理开销较大。
    
- **多对多**：n个用户级线程映射到 m 个内核级线程，$n \ge m$，多个用户线程对应多个内核线程，内核线程数不多于用户线程数。兼顾并行能力与管理开销，兼具上面两者优点。
    

注意：**内核只直接调度内核级线程；用户级线程由线程库调度到可用的内核级线程上。**

**线程库的实现**

线程库提供创建、终止、等待线程及线程同步等接口，主要有两种实现方式：

- **用户级实现**：线程库的代码和数据位于用户空间，线程管理通过普通函数调用完成，无需内核直接参与，开销较小。
    
- **内核支持实现**：线程库通过系统调用请求内核服务，由内核管理和调度线程，涉及用户态与内核态切换，开销较大，但可利用多核并行。

线程库提供创建、终止、等待线程及线程同步等接口，主要有两种实现方式：

## 2.2 CPU调度

### 2.2.1 调度的概念

**1. 调度的基本概念**

当多个任务竞争资源时，操作系统按照一定算法选择任务，并为其分配资源。

**CPU调度**是从就绪队列中选出一个进程或线程，分配CPU使其运行，以提高CPU利用率，并兼顾公平性和响应速度。

**2. 调度的层次**

| 层次             | 调度对象       | 主要作用            | 频率               |
| -------------- | ---------- | --------------- | ---------------- |
| **高级调度（作业调度）** | 外存后备队列中的作业 | 选择作业调入内存，建立相应进程 | 低，整个生命周期只有一次调入调出 |
| **中级调度（内存调度）** | 挂起的进程      | 选择合适的进程重新调入内存   | 中                |
| **低级调度（进程调度）** | 就绪进程或线程    | 选择任务分配CPU       | 高                |

- **高级调度**：决定“哪些作业进入内存”。作业是用户提交的一项任务，通常包含程序、数据和作业说明。
    
- **中级调度**：决定“哪些挂起进程恢复到内存”。内存紧张时，可将部分进程调至外存，条件合适后再调回。
    
- **低级调度**：决定“哪个就绪任务获得CPU”，是操作系统中最基本的调度。

挂起是放到外存中了，被挂起的PCB组织成为挂起队列

**3. 三级调度的联系**

典型过程：

外存后备作业 → **高级调度** → 内存就绪进程 → **低级调度** → CPU运行。

进程被调至外存后进入挂起状态，再通过**中级调度**恢复到内存，具备运行条件后参与低级调度。

- 高级调度控制进入系统参与竞争的作业数量。
    
- 中级调度调节内存中的进程数量，缓解内存压力。
    
- 低级调度分配CPU，使就绪任务交替运行。
    
- 并非所有系统都有完整的三级调度，但通常都需要低级调度。
    

### 2.2.2 进程调度

**1. 进程调度任务**

- 保存CPU现场信息
- 选取待运行进程
- 完成CPU分配

**2. 调度程序（调度器）**

- **排队器**：按照调度策略，将就绪进程组织成一个或多个队列。
    
- **分配器**：根据调度算法，从就绪队列中选出下一运行进程。
    
- **上下文切换器**：保存原进程的运行现场，恢复选中进程的现场，完成CPU控制权的交接。
    

**3. 调度的时机、切换和过程**

需要调度的典型情况：
- 创建新进程后

- 当前进程终止。
    
- 当前进程因I/O、资源或事件进入阻塞态。
    
- 时间片用完。
    
- 更高优先级任务就绪，满足抢占条件。
    

通常不能立即调度的情况：

- 正在处理中断。
    
- 正在执行需要保护的内核临界区。
    
- 正在执行关中断等不可中断的原子操作。
    

注意：**访问普通用户临界区不一定禁止调度**；处于内核态也不意味着始终不能调度。

切换过程：

保存原进程CPU现场至PCB → 更新状态和队列 → 选择下一进程 → 切换运行环境、恢复现场 → 继续执行。

**调度不一定发生进程切换**：如果仍选中原进程，可继续运行。进程切换存在开销，过于频繁会降低效率。

**4. 进程调度的方式**

- **非抢占式（非剥夺式）**：进程获得CPU后，直到结束、阻塞或主动让出，其他进程才能运行。实现简单，但响应速度可能较慢。
    
- **抢占式（剥夺式）**：操作系统可在时间片用完、更高优先级任务就绪等情况下收回CPU。响应较快，适合分时和实时系统，但管理开销较大。
    

**5. 闲逛进程**

当没有其他就绪任务时，CPU运行**闲逛进程（空闲任务）**。

- 优先级最低，不处理实际业务。
    
- 可执行等待指令，使CPU进入低功耗状态。
    
- 一旦有其他任务就绪，便让出CPU。
    

**6. 两种线程的调度**

- **用户级线程调度**：由用户态线程库决定哪个用户线程运行，内核不能直接感知，切换通常无需进入内核。若一个线程执行阻塞操作，整个进程都会阻塞
    
- **内核级线程调度**：由内核决定哪个内核线程获得CPU，可在多个CPU核心上并行运行，切换通常需要内核参与。切换开销大
